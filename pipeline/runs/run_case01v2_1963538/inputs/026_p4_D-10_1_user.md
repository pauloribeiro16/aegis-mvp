## Cross-recipient map

#### Cross-recipient map
D-10.1 generates a layered recipient set on the **continuous-monitoring evidence trail**. ## Scope-overlap principle (operational)

#### Scope-overlap principle (operational)
The high-level SO (`SG-D-10.1.HL`) engages on a given party **if and only if ≥2 applicable regulations have ≥1 Y or Conditional-Y-scope-overlap pair on the same party** (e.g. a DORA financial entity that is also a controller processing personal data through high-risk AI — a vertically-integrated financial-controller-AI-provider with GDPR + DORA + AI Act applicability on the layered 5-monitoring-architecture). For a CRA-regulated manufacturer that is also a controller (controller-manufacturer), the GDPR + CRA sub-SOs activate on **two different artefacts** (entity-level 5-risk-type monitoring vs. product-level on-device internal-activity monitoring) — the two regimes meet at the controller-manufacturer interface, **but the CRDA-flagged GENUINE TENSION (CRA user opt-out vs. GDPR mandatory monitoring) requires Layer 2 OJ-level resolution**. For an entity with GDPR + CRA + DORA applicability, the three sub-SOs activate with the CRA opt-out conflict propagating against both GDPR and DORA mandatory monitoring. The five monitoring mandates are stacked, not collapsed: 5-risk-type detection (GDPR) + all-hazards incident-handling detection capability (NIS 2 partial) + on-device internal-activity monitoring with user opt-out (CRA) + continuous ICT-system monitoring (DORA) + AI-system post-market monitoring (AI Act). The high-level SO surfaces the common continuous-monitoring duty but does **NOT** collapse the per-reg anchor, scope dimension, trigger, threshold, recipient, or content template, **and does NOT resolve the CRDA-flagged GENUINE TENSION**.
