The verification surfaced four baseline-change proposals, tabled here for per-item client verdicts (ADR-005): **Accept** / **Reject** (= explicit risk acceptance, recorded, never silent) / **Adjust**.

## §1 Proposals

| # | Proposal | Motivation (evidence) | Recommendation |
|---|---|---|---|
| **P1** | Add Volere fit criteria for the two carriers that lack them: **RN5** (recoverability NFR) and the **R1.2** rectification elevation (driver `PO-D-01.4-001`). | PRIN-ENG-05 requires a deterministic pass/fail criterion on every accepted carrier; neither has one. No wording change to the delivered cards. | **Accept** — completes the formulation record; zero delivered-text impact. |
| **P2** | Widen **RN27**'s EARS trigger from "a data-subject request to export or erase" to "a data-subject request under Art. 15–22", and extend its fit criterion with the minimisation-constrained-verification leg. | Closes the `SO-D-03.1-001` scope gap (access, rectification, restriction, objection requests currently unverified before execution). Baseline wording change (MUST). | **Accept** — same response, larger trigger set; proportionate to an 8-person SaaS (single verification function for all rights requests). |
| **P3** | Widen **RN18**'s trigger set to include data access/modification events ("relevant internal activity" scope) and restore the *user deletions* trigger. | Both objectives' statements demand recording of "access to or modification of data, services or functions"; the current enumerated triggers omit the largest event class. Baseline wording change (MUST). | **Accept** — closes the trigger-scope gap against the drivers' demand. |
| **P4** | Corruption-reporting leg of `SO-D-01.4-002` ("corruption or unauthorised modification is reported"): **(a)** record as organizational carve-out (integrity validation already exists on write paths via RN15/RN16; corruption alerting is an ops/monitoring process at this scale), or **(b)** derive a new constraint (RN31: "If corruption or unauthorised modification of stored billing or subscription state is detected, the system shall report it to the administering party"). | No carrier exists for the reporting leg. | **(a) Accept carve-out** — alerting/routing to humans is operational process at 8-person scale; integrity detection is already product-carried. Alternative (b) available if the researcher prefers product-side reporting. |
